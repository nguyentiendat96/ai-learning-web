def apply_edit(text, edit):
    find = edit["find"]
    replace = edit["replace"]
    if not find:
        raise ValueError("Đoạn find rỗng — không có gì để thay")
    index = text.find(find)
    if index == -1:
        raise ValueError(f"Không tìm thấy đoạn cần thay: {find!r}")
    return text[:index] + replace + text[index + len(find):]
def apply_edit(text, edit):
    find = edit["find"]

    for line in hunk.splitlines():
        if line.startswith("---") or line.startswith("+++"):
            continue                      # header tên file, không phải dòng thay đổi
        if line.startswith("-"):
            removed += 1
        elif line.startswith("+"):
            added += 1
        # dòng ngữ cảnh và header "@@": bỏ qua
    return removed, added
def count_changes(hunk):
    removed = 0
    added = 0
    for line in hunk.splitlines():
        if line.startswith("---") or line.startswith("+++"):
            continue                      # file-name header, not a change line
        if line.startswith("-"):
            removed += 1
        elif line.startswith("+"):
            added += 1
        # context lines and "@@" headers: skip
    return removed, added

Vài ghi chú:A few notes:

  • Kiểm tra header trước dấu -/+, nếu không --- a/settings.py sẽ bị đếm nhầm thành một dòng bỏ.Check the headers before the -/+ prefixes, otherwise --- a/settings.py gets miscounted as a removed line.
  • Đây là bản đơn giản: nội dung một dòng bị bỏ mà tự nó bắt đầu bằng -- sẽ bị bỏ sót — diff thật phân biệt nhờ vị trí trong hunk. Hiểu giới hạn này là hiểu vì sao cần parser thật cho patch.This is the simple version: a removed line whose content itself starts with -- will be missed — real diffs distinguish them by position in the hunk. Understanding this limitation is understanding why a real patch parser is needed.
  • Đếm kiểu này chính là cách ước lượng "độ lớn" một bản sửa. Nhớ lại mục 5: Aider dùng unified diff rút gọn (bỏ số dòng hunk), còn Codex dùng file-operation patch có ngữ cảnh mà không cần đếm dòng.Counting this way is exactly how you estimate the "size" of a fix.
